# Frontend 3D (PlumeTrace)

The 3D station is the hero of the LinkedIn video and the first thing a visitor sees. It must look
like a real compressor station, stay at **60 fps at 1080p on integrated graphics**, and never show
something the physics did not produce.

Read first: the design (section 9), `frontend-design` (visual direction, control-room reference),
`frontend-structure` (feature boundaries, data sources, state). Then the reference you need:

**Chosen approach: B — Blender-baked.** The static station is generated by a bpy script from the
facility spec, lighting/AO are baked, and the compressed glTF is loaded by R3F; everything dynamic
is real-time on top. A 2-day spike validates it first; if it fails, fall back to approach A
(procedural R3F components). All tools are free (Blender, glTF-Transform, Poly Haven CC0).

- [Blender pipeline](references/blender-pipeline.md) — **read first**: flow, commands, bpy package layout, naming contracts, budgets, the spike and the fallback.
- [procedural equipment](references/procedural-equipment.md) — what each equipment type must look like and its parts (used by the bpy generator in B, and by R3F components in fallback A).
- [plume and effects](references/plume-and-effects.md) — GPU plume particles, ground heat-map, wind indicator, candidate highlighting, flare, selective bloom.
- [performance and testing](references/performance-and-testing.md) — budgets, R3F pitfalls, quality tiers, measuring fps, test-renderer and visual tests.

**Check the docs first.** Verify every API against the pinned versions of `three`,
`@react-three/fiber` (v9 line targets React 19), `@react-three/drei` and
`@react-three/postprocessing` with the Context7 docs tool before writing code.

## Hard rules

1. **Data drives geometry.** Every equipment item comes from the facility spec (`ks07.yaml`):
   the bpy generator builds it, the glb carries tag-named nodes and `<tag>.<anchor>` empties, and
   the frontend finds things only through `nodeIndex` — never by hard-coded positions or by
   hand-modelling in Blender. A test asserts every spec tag and anchor exists in the glb.
2. **Physics drives the plume.** Plume direction, extent and density come from the plume field
   the backend computed (live: WebSocket; replay: trace file). The frontend never re-implements the
   Gaussian plume; it only renders the field (and interpolates between frames).
3. **No per-frame React state.** Animate in `useFrame` by mutating refs; never call `setState` in
   `useFrame`. Read high-frequency store values with `useStore.getState()` or transient
   subscriptions inside `useFrame`. No `new THREE.Vector3()` / `.clone()` inside `useFrame` —
   use module-level temporaries. Enforce with `@react-three/eslint-plugin`.
4. **Share and instance.** One geometry and one material instance per unique look, created once
   (module scope or `useMemo`) and reused. Anything repeated more than ~10 times (valves, flanges,
   bolts, supports, grating panels, handrail posts) is instanced. Static, never-selected clutter
   is merged into one geometry.
5. **Budgets (1080p, integrated GPU):** ≤ 300 draw calls, ≤ 1.5 M triangles, `ks07.glb`
   ≤ 15 MB (meshopt + WebP), ambient occlusion baked, one real-time sun with a ≤ 2048 shadow map,
   plume ≤ 40 k particles on "high" and ≤ 10 k on "low", texture memory ≤ 128 MB. Check `gl.info`
   after each scene feature.
6. **Quality tiers.** `high | medium | low`, chosen by `PerformanceMonitor` (decline → drop tier)
   and overridable in settings. Tiers change dpr (cap `[1, 1.5]` high, `1` low), shadows, bloom,
   particle count and detail level. `prefers-reduced-motion` → no automatic camera flights and
   slower plume animation.
7. **No external network at runtime.** Environment maps (HDR), fonts for 3D text and textures are
   local files in `app/frontend/public/`; never use drei presets or default fonts that download
   from a CDN (they break the Vercel CSP and offline use). Verify each drei component's default
   asset behaviour in its docs.
8. **Picking is cheap.** Pointer events only on one simple hit-proxy per equipment item
   (invisible box); decorative meshes and instanced clutter set `raycast` to a no-op.
   Always `stopPropagation` in handlers.
9. **Accessible and resilient.** The canvas sits in a lazy boundary with an error boundary and a
   static fallback image; a DOM list of equipment mirrors the scene so selection works by
   keyboard and screen reader; selection in the list highlights in 3D and vice versa.
10. **Honest visuals.** Colours for alarms and AI candidates follow the control-room palette;
    candidate glow strength reflects the inversion's posterior probability; nothing glows that
    the data does not support. Simulated scenes are labelled simulated.
11. **No god components.** One component per equipment type or effect; a component file stays
    under the repo's line limit (see `repo-structure`). Split by part (vessel, nozzles,
    platform), not by arbitrary chunks.
12. **Clean up.** Shared materials/geometries are disposed only when the canvas unmounts;
    components using shared resources set `dispose={null}` on primitives that must outlive them.
    Event listeners added in effects are removed in the cleanup.

## Definition of done for a 3D task
- Docs checked against pinned versions (three, R3F, drei, Blender, glTF-Transform); geometry
  regenerated from the spec by the pipeline, never edited by hand.
- Tests: scene-graph test with `@react-three/test-renderer` (counts, selection, frame advance)
  and a Playwright screenshot at the fixed review camera.
- `gl.info` draw calls / triangles recorded in `docs/WORK_LOG.md`; still within budget.
- fps measured on the review camera at "high" (record hardware), reduced-motion path checked.
- `docs/reference/FRONTEND.md` 3D section updated (rule 17 in CLAUDE.md).
