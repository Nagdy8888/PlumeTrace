# Blender bake pipeline (approach B — the chosen approach)

The static station is **generated by a Blender Python (bpy) script from the facility spec**, its
lighting and ambient occlusion are **baked** into textures, and the result is exported as one
compressed glTF that React Three Fiber loads. Everything that changes at runtime (plume, heat-map,
highlights, labels, fan rotation, flare flame, camera) stays real-time in R3F on top.

All tools are free: Blender (GPL), Blender's glTF exporter, glTF-Transform (MIT), Poly Haven
textures and HDRIs (CC0). Lighting in the browser is real-time (HDRI + one sun) on top of the baked
ambient occlusion — glTF has no standard lightmap slot, so AO is what gets baked. Pin every version and record it in
`docs/reference/FRONTEND.md`. Blender is installed by the owner from blender.org (an LTS release).

## Flow
```text
app/backend/plumetrace/facility/ks07.yaml  (single source of truth)
        │  scripts/export_contract.py → app/frontend/src/shared/facility/ks07.json
        │  scripts/blender/  (bpy package, run headless, reads ks07.json with stdlib json)
        ▼
Blender scene: equipment from parts library, piping along routes, procedural flanges/valves,
named empties for anchors (VS-250.tip, K-202.packing, TK-402.thief_hatch …)
        │  Cycles bake: ambient occlusion per equipment into a second UV set (glTF occlusionTexture)
        ▼
glTF export (.glb) with node names = tags, KHR_materials, EXT_mesh_gpu_instancing for repeats
        │  glTF-Transform: dedup, prune, instance, meshopt geometry, WebP textures, resize
        ▼
app/frontend/public/models/ks07.glb   (generated — never hand-edited, never hand-modelled)
        │  R3F useGLTF → nodeIndex (tag → node) → hit proxies, highlight, anchors
        ▼
Real-time layer: plume, heat-map, candidate glow, labels, fans, flare, camera
```

## Commands (versions pinned in `scripts/blender/README` header and FRONTEND.md)
```bash
blender --background --factory-startup --python scripts/blender/build_station.py -- \
  --spec app/frontend/src/shared/facility/ks07.json --out build/ks07_raw.glb --bake high
npx @gltf-transform/cli@<pinned> optimize build/ks07_raw.glb app/frontend/public/models/ks07.glb \
  --compress meshopt --texture-compress webp --texture-size 1024 \
  --join false --flatten false --simplify false --palette false --prune false
```
The `false` flags are required: default `optimize` joins meshes, flattens the hierarchy and prunes unused and empty nodes, which would delete tag nodes and anchor empties. (`--prune-leaves` does not exist in `@gltf-transform/cli` 4.5.1; use `--prune false`. Owner ruling 2026-11-15.) In Blender 4.5.16 the glTF exporter keyword for UV export is `export_texcoords` (plural), not `export_texcoord`. `build/` is a git-ignored scratch folder. `--bake low` gives a fast preview bake for iteration.

## bpy package layout (`scripts/blender/`, "no god files" limits apply)
```text
scripts/blender/
├── build_station.py     entry: parse args, run steps, export
├── spec_loader.py       read ks07.json (stdlib json; Blender's Python has no uv env) — no bpy
├── naming.py, uvmath.py, layout.py   pure helpers (no bpy), unit-tested from the uv env
├── polyhaven_manifest.json           asset ids, maps, resolution, SHA-256 (scripts/fetch_polyhaven.py)
├── parts/               vessel.py, nozzle.py, skid.py, platform.py, ladder.py, handrail.py, flange.py
├── equipment/           compressor.py, scrubber.py, fin_fan.py, teg.py, tank.py, flare.py,
│                        vent_stack.py, shelter.py, pig_trap.py, pipe_route.py, pipe_rack.py
├── materials.py         node materials from Poly Haven CC0 textures (local files)
├── lighting.py          HDRI world + sun at the baked time of day
├── bake.py              second UV set, Cycles AO bake, image packing (occlusionTexture)
└── export.py            glTF export settings, node naming, anchor empties
```
Each module has Google docstrings and stays under the size limits. Blender's bundled Python runs
these scripts; they never import `plumetrace` (they read the generated `ks07.json`). Modules that
import `bpy` contain only Blender calls; all maths and naming live in the pure helpers so they can
be tested with pytest. Source textures (Poly Haven CC0, 1k JPG) are downloaded by
`scripts/fetch_polyhaven.py` into the git-ignored `build/polyhaven/`; only the HDRI used at runtime
is committed (`app/frontend/public/textures/env/`). Coordinates: spec and Blender are Z-up
(x east, y north); the glTF exporter's +Y-up conversion gives three.js `(x, z, −y)`.

## Rules
1. **Spec-driven only.** No manual modelling or clicking in Blender; rerunning the script
   reproduces the model exactly (seeded randomness for wear/variation).
2. **Names are contracts.** Node names = equipment tags; anchor empties = `<tag>.<anchor>`; the
   frontend `nodeIndex` and the backend candidate list use the same ids. A test asserts every
   spec tag and anchor exists in the exported glb.
3. **Budgets:** `ks07.glb` ≤ 15 MB after optimisation; ≤ 1.5 M triangles; AO textures ≤ 1024² per equipment, WebP; draw calls ≤ 300 after instancing/merging.
4. **One baked time of day** (golden hour). Night mode = global tint/exposure change plus emissive
   lights from the real-time layer; no second bake in MVP.
5. **Interactive parts stay separate:** fan blades, the flare tip and anything the camera targets
   are exported as separate nodes so R3F can animate/highlight them without re-baking.
6. **Fallback (approach A):** if the spike fails (looks, 60 fps or size), the same `parts/` and
   `equipment/` designs are implemented as R3F components instead (see `procedural-equipment.md`),
   with real-time AO and CC0 textures. Spec, tags and anchors do not change.
